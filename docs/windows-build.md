# Windows x64 build (MinGW-w64 cross build, GL back end)

A `pcj.exe` for Windows x86-64 (and Wine / Whisky on macOS), built on this Linux host with
MinGW-w64 and the toolkit's own Windows support (`xboxrecomp/cmake/mingw-w64-x86_64.cmake`:
platform layer = real Win32, memory layout = VirtualAlloc/MapViewOfFileEx, MMIO traps = VEH,
audio = XAudio2 then waveOut, toolkit D3D/present = D3D11, input = XInput). Rendering is our GL
3.3 back end (`src/gl_backend.c`) over SDL2 + libepoxy, as on Linux.

## Toolchain and dependencies

    apt-get install gcc-mingw-w64-x86-64-posix g++-mingw-w64-x86-64-posix mingw-w64-x86-64-dev wine64
    pip install meson          # only to build libepoxy

`win-deps/` (not part of the source tree, ~75 MB + the Wine prefix):

- `win-deps/sdl2/{include,lib,bin}`: SDL2 2.30.9 MinGW devel release
  (github.com/libsdl-org/SDL/releases, `SDL2-devel-2.30.9-mingw.tar.gz`, x86_64-w64-mingw32 dir).
- `win-deps/epoxy/`: libepoxy 1.5.10 (git tag), cross-built:
  `meson setup <b> --cross-file win-deps/dl/mingw.cross -Dprefix=$PWD/win-deps/epoxy -Degl=no -Dx11=false -Dtests=false -Ddocs=false --buildtype=release && ninja -C <b> install`
  (cross file: `x86_64-w64-mingw32-gcc-posix`, system windows, cpu x86_64). repo.msys2.org is
  blocked from this host, hence the source build.
- `win-deps/wineprefix`: 64-bit Wine prefix for the tests (`wine64 wineboot -i`, 1.3 GB).

## Build

    cmake -S . -B build-win -DCMAKE_TOOLCHAIN_FILE=xboxrecomp/cmake/mingw-w64-x86_64.cmake \
          -DCMAKE_C_COMPILER=x86_64-w64-mingw32-gcc-posix -DCMAKE_CXX_COMPILER=x86_64-w64-mingw32-g++-posix \
          -DCMAKE_BUILD_TYPE=Release
    cmake --build build-win -j2 --target pcj        # about 4 min on 2 cores
    tools/package_win.sh                             # -> dist/pcj-win64-<date>.zip

Same gen dir (`src/recomp/gen`), same hybrid swaps (regenerated by `tools/hybridize` from the
read-only pcj-decomp), same toolkit patches as the Linux build. Build only the `pcj` target
(the toolkit's Windows `d3d8_smoke` test is not needed). Runtime DLLs: `SDL2.dll`,
`libepoxy-0.dll`, `libwinpthread-1.dll` (libgcc/libstdc++ are static); everything else is a
Windows system DLL (opengl32, d3d11, D3DCOMPILER_47, XAudio2_8, XINPUT1_4, MFPlat, winmm, ...).

## What was ported

| piece | Linux | Windows |
|---|---|---|
| fault handler (`src/main.c`) | SIGSEGV/SIGBUS -> `xbox_PosixMmioFault` | VEH registered *last* (`AddVectoredExceptionHandler(0, ...)`) so the toolkit's AC97/watch VEHs run first; calls `xbox_VehMmioFault`, otherwise logs `[CRASH]` + guest registers + guest return chain and exits (code 3). Only AV / illegal / stack overflow / div0 / in-page are treated as crashes |
| settings | run.sh exports `RECOMP_*` | `pcj.ini` next to the exe (`game=`, `save=`, any other `KEY=VALUE` -> environment unless already set), then built-in defaults: `RECOMP_AC97_READY=1 RECOMP_TITLE_KEVENTS=1 RECOMP_VBLANK=1 RECOMP_PB_EXEC=1 CJ_GL=1 CJ_PAD_HOST=1`. Game dir: argv[1] > `PCJ_GAME_DIR` > ini > exe dir if it holds default.xbe. Save dir: argv[2] > `PCJ_SAVE_DIR` > ini > `<exe dir>\save` |
| log | stdout/stderr | `pcj-log.txt` next to the exe (`PCJ_LOG=<file>`, `PCJ_LOG=-` = console). Logs the Wine version when under Wine. Message boxes for "no game dir", "no XBE", "memory layout failed" |
| GL registration | constructor reading `CJ_GL` | `cj_gl_register_env()` called from `main` after the ini/defaults (constructors run before them) |
| GL context (`src/gl_backend.c`) | 3.3 core | 3.3 core **forward-compatible** (what macOS GL 4.1 core needs under Wine/Whisky; the back end uses no compatibility-profile calls, GLSL `330 core`, UBO binding 0 by default, no extension beyond 3.3) |
| window | 640x480 | 640x480 x `CJ_WINDOW_SCALE` (default 2, shrunk to fit the desktop), resizable, aspect-correct letterbox blit, F11 / Alt+Enter desktop fullscreen, `CJ_FULLSCREEN=1`, `CJ_VSYNC=1`; window close exits |
| fps | `[GL] flip` line every 16 flips | also window title `... - NN.N fps` every second and `[FPS]` log line every 5 s (both hosts) |
| pad (`src/cj_pad.c`) | `-Wl,--wrap` XAPI wrappers, scripted | same wrappers (MinGW ld has `--wrap`); plus `CJ_PAD_HOST=1` (Windows default): `gl_flip` samples SDL GameController + keyboard after its event pump into `cj_host_pad`, `XInputGetState` ORs it with the script (`CJ_PAD_SCRIPT/REPEAT/LIVE` still work). Keyboard map in README-PC.txt and `host_input()` |
| audio | emulated APU -> SDL2 | emulated APU -> XAudio2 -> waveOut (toolkit). `xa2_init` is wrapped (`-Wl,--wrap=xa2_init`, `src/main.c`): skipped when `waveOutGetNumDevs()==0` or `CJ_AUDIO_XA2=0`, because Wine's XAudio2 (FAudio) faults inside CreateMasteringVoice with no output device |
| CJ_DET | full | compiles and runs (winpthreads gives pthread / clock_gettime / clock_nanosleep); `CJ_DET_WATCH` (perf_event hardware watchpoint) is Linux only; `setenv` -> `_putenv`; the hybrid SIGUSR1 stall dump is POSIX only |
| frame pacing | `clock_nanosleep` | same (winpthreads) + `timeBeginPeriod(1)` |
| weak symbols | `cj_gl_flips` weak | plain extern (PE has no weak undefined; gl_backend.c is always linked) |

Linux behaviour is unchanged except: the window is now resizable/scaled (`CJ_WINDOW_SCALE`, default
2; headless Xvfb runs are unaffected: `CJ_GL_DUMP` reads the FBO, not the window), the fps title/log,
and `CJ_PAD_HOST=1` is available on Linux too.

## Testing under Wine here

    tools/run_wine.sh                       # like run.sh: dist/stage/pcj.exe under wine64, PCJ_LOG=-
    PCJ_RUN=tools/run_wine.sh python3 tools/route.py <tag> --until level --after 400 --dump-every 60 --skip

`tools/route.py` takes the launcher from `PCJ_RUN` (default `./run.sh`). Wine imports the Unix
environment, so `CJ_PAD_LIVE`/`CJ_GL_DUMP` paths work (the process cwd is on Z:).
`dist/stage/` holds the exe + DLLs (`tools/package_win.sh` refreshes it).

Results: see "Wine test" below.

## Wine test

Run W1 (`PCJ_RUN=tools/run_wine.sh python3 tools/route.py W1 --until level --after 400 --dump-every 60 --skip`,
Wine 9.0 wine64, Xvfb + llvmpipe on 2 cores, context "4.5 Core Profile Mesa 25.2.8" through Wine's
opengl32): **boot -> FMVs -> main menu (flip 751, 58 s) -> New Game -> hub -> level 1 loaded (flip
1629) -> gameplay with player control (flip 1652), DONE at flip 2064 (297 s), no crash.** Frames
`run/W1/fr/g00780.ppm` (main menu, logo/text/legend intact) and `g02040.ppm` (level 1, Predator,
HUD, radar) match the Linux GL frames.

flips/s, harmonic mean of the route's 64-flip windows (same route, same host):

| phase | Wine (W1) | native Linux (V2, docs/gl-backend.md) |
|---|---|---|
| boot / FMV / title | 13.4 (4.7-23.4) | 9.2 (1.9-21.8) |
| main menu + New Game dialogs | 4.7 (3.5-6.0) | 6.4 (5.9-7.9) |
| hub | 4.9 | 6.1 |
| level 1 (intro skip + gameplay) | 6.1 (4.8-11.8) | 7.5 (5.3-18.4) |

So Wine costs ~20-25% on this CPU-bound llvmpipe host (the GL thunks and Wine's syscall layer
on ~2500 draws/flip); a real GPU driver should move the bottleneck to the executor's CPU work.

Real input was checked separately (run kt): XTest key presses into the Xvfb window under Wine
reach the XAPI wrapper (`[PAD] host input: dig 0010` for Enter = Start, `ana ff..` for Space = A)
and drive the front end from the title to New Game with no script.

Packaged-zip check: unzipped `dist/pcj-win64-*.zip`, set `game=` in pcj.ini, started `pcj.exe`
with no arguments: ini read, game dir from the ini, `save\` created next to the exe,
`pcj-log.txt` written with `[FPS]` lines.

Found and fixed on the way: (1) the VEH was first in the chain and swallowed the toolkit's AC97
trap (crash at guest 0xFEC0012C): now registered last; (2) Wine's XAudio2 faults with no audio
device: `xa2_init` wrapped (see table). The save folder holds ~5 GB of partition images
(sparse on Linux/APFS, allocated on NTFS).

## Update 2026-10-20: guest window check, movie audio, renderer fixes

- **Patch 0009** (`patches/v0.15/0009-guest-window-free-check.patch`, Windows only): before a fixed
  base is used, `VirtualQuery` checks that the **whole 4 GB guest window** above it is free (mirrors,
  contiguous window and tiled aperture are mapped at fixed offsets from it later), skipping bases
  that collide (`base %p skipped, guest window not free at %p`); adds high bases 0x200000000,
  0x400000000, 0x800000000, 0x1000000000 (Wine on arm64 macOS/Rosetta keeps its own image at
  0x100000000, inside every low base's window: error 487 on the aperture and top mirrors); and
  `RECOMP_GUEST_BASE=<hex>` forces a base. A Whisky test run got to level 1 with it.
- **Movies (`CJ_MOVIE_AUDIO`, src/det_file.c)**: an XMV movie with its audio stream fetches the next
  packet only after DirectSound completed the previous one, and shifts presentation times by the
  audio offset, so a host whose emulated APU runs behind (XAudio2 underruns on a starved Mac) makes
  the video stutter or stall. The `XMVDecoder_EnableAudioStream` wrapper now decides per movie:
  `CJ_MOVIE_AUDIO=1` original behaviour, `=0` silent movies paced by the vblank count alone (the
  CJ_DET path), unset = auto: audio stream off when the host audio has already underrun
  `CJ_MOVIE_AUDIO_UNDERRUNS` (default 3) times. Logged as `[MOVIE] audio stream on|off ...`.
  Put `CJ_MOVIE_AUDIO=0` in `pcj.ini` if movies still stall. Not reproducible here: this host's Wine
  has no audio device (XAudio2 skipped, APU paced by the host clock), so the W2 run below only
  checks the movies still play.
- **Run W2** (Wine, this build, `PCJ_RUN=tools/run_wine.sh tools/route.py W2 --until level --after 200 --skip`):
  boot, all intro movies (`[MOVIE] audio stream on`, 0 underruns), title, main menu, New Game, no
  crash in 14 min / 3900 flips; it did **not** reach level 1: the route looped between New_Game/12
  and /13 (the save-overwrite prompt with the Wine save dir `run/save-win`), a route.py issue,
  stopped by hand. The Linux route R2 (same sources) reached gameplay. Zip: `dist/pcj-win64-20261020.zip`.
- Renderer: radar clip, mip chains / sampler state, window clip, polygon offset (docs/gl-backend.md,
  top section).


## macOS / Whisky notes

- Whisky's D3DMetal path is for D3D11/12; an OpenGL program goes through Wine's opengl32 ->
  winemac.drv -> macOS OpenGL 4.1 core (on Apple Silicon: Apple's GL-over-Metal). The context
  is requested as 3.3 core forward-compatible, which that path supports. It is the least tested
  part: if it fails, the log shows the `[GL] window/context:` error and the run stops at the
  first flip.
- The guest memory window: Wine 9 has no VirtualAlloc2/MapViewOfFile3, so the toolkit uses its
  fixed-base list (base 0x10000 here, `RAM mirror: 28/28 views` covering 1.8 GB of low address
  space). Whether macOS Wine (Rosetta) leaves that low
  address range free is untested; if a mapping fails the log says which
  (`xbox_MemoryLayoutInit: ...`) and `[FATAL]` + a message box follow.
- Long term, a D3D11 back end (the toolkit's own Windows D3D11 path / the apexJCL fork) would
  run on D3DMetal and is the better route for Whisky.

## clang build (default for shipped builds, 2026-10-21)

`cmake -S . -B build-winclang -DCMAKE_TOOLCHAIN_FILE=$PWD/cmake/mingw-clang.cmake -DCMAKE_BUILD_TYPE=Release -DCJ_WIN_DEPS=$PWD/win-deps`
then `cmake --build build-winclang`. Same MinGW-w64 headers, libs and ld; clang
gives native TLS for the per-thread guest registers (g_eax.. g_esp, __thread).
MinGW GCC 13 only has emutls: every register access in generated code calls
__emutls_get_address -> winpthreads pthread_getspecific (GetLastError, spin
lock, SetLastError). The src/prof.c profile put that at ~2/3 of the game
thread's own work under Wine. The hybrid C++ must be built with
-fno-strict-aliasing -fwrapv -fno-delete-null-pointer-checks (CMakeLists.txt):
without them clang's build drew the Movement Training ground black.
tools/package_win.sh packages build-winclang when it exists and keeps the
unstripped exe in dist/symbols/ for tools/prof_report.py.
